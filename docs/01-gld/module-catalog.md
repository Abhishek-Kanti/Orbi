## 2. Detailed Module Specifications (`MOD-01` – `MOD-18`)

### `MOD-01`: Channel Gateway & Telegram Adapter
- **Purpose**: Normalizes inbound interactions from Telegram into channel-agnostic platform requests (`ChannelAdapterPort`), maps Telegram sender identities into household-ready user principals (`ADR-002`, `ASM-07`), renders task notifications, ordinary `INFORMATION_REQUEST` / `PHYSICAL_ACTION_REQUEST` / `APPROVAL_REQUEST` prompts pushed by `MOD-18`, and emits short-lived authenticated Dashboard handoff deep-links whenever an interaction requires `SECURE_INPUT_REQUEST` or `HUMAN_TAKEOVER`. **Never** collects OTPs, passwords, or sensitive credentials directly over Telegram (`NFR-SEC-06`).
- **Status**: `[CONFIRMED]` (Zone 1: Python 3.12+ / FastAPI inside `orbi-core`).
- **Owned State**: Channel identity bindings (`telegram_user_id`, `telegram_chat_id` <-> `user:<id>`, `household:<id>`, `active_task_id`) in `orbi_app`.
- **Public Interfaces**:
  - *Inbound*: Telegram Bot webhooks / updates (`text`, attachments, `INFORMATION_REQUEST` answers, inline approval callbacks carrying `interaction_id`, `approval_id`, `payload_digest`), formatted notifications & interactive prompts pushed by `MOD-18` (from `MOD-03`/`MOD-17`).
  - *Outbound*: Submits normalized `TaskRequest` and `InteractionResponse` (`INFORMATION_REQUEST`, `APPROVAL_REQUEST`, `PHYSICAL_ACTION_REQUEST`) commands to `MOD-03` (`HumanInteractionManager`); consumes delivery events from `MOD-18`.
- **Allowed Dependencies**: `MOD-03`, `MOD-09` (channel/user verification), `MOD-15`, `MOD-18`.
- **Forbidden Dependencies**: Must never invoke `MOD-04` agents directly, execute `MOD-08` tools, interpret chat text as direct task approval without `MOD-03`, collect plaintext `SECURE_INPUT_REQUEST` secrets, or read raw Memory Manager/SaaS secrets.
- **Independent Testability (`AP-08`)**: Tested via mocked Telegram webhook payloads against fake `MOD-03`/`MOD-09`/`MOD-18` interfaces.

### `MOD-02`: Admin, Monitoring, Approval & Memory Dashboard
- **Purpose**: Operator control plane providing visibility into tasks (`WAITING_FOR_USER`), **centralized HITL interaction queues**, **authenticated LLM-bypassing `SECURE_INPUT_REQUEST` entry**, time-bounded **noVNC/WebRTC `HUMAN_TAKEOVER`** sessions (`MOD-13`/`MOD-14`), **`MOD-10` `NEEDS_CLARIFICATION` memory curation & quarantine**, explicit forgetting (`FR-MS-14`), **autonomous automations & ongoing `AgentResponsibility` work plans**, schedule version history, condition monitors, delegation lineage, audit trails, OpenFGA household/agent policies, pending action-bound approvals (full canonical arguments & target inspection), and Markdown skill package review/publication.
- **Status**: `[CONFIRMED]` *(Frontend framework open for HLD under `OQ-01`; BFF endpoints in FastAPI `orbi-core`)*.
- **Owned State**: UI session tokens only (zero duplicate copies of tasks, interactions, automations, memories, or skills; zero persistent `SECURE_INPUT_REQUEST` secret storage).
- **Public Interfaces**:
  - *Inbound*: Independently authenticated HTTPS requests from authorized household/owner browsers (including replay-protected Telegram handoff sessions verified cleanly) + live updates from `MOD-18`.
  - *Outbound*: Calls BFF REST/WebSocket endpoints backed by `MOD-03` (`HumanInteractionManager`), `MOD-06`, `MOD-07`, `MOD-09`, `MOD-10`, `MOD-11`, `MOD-13`, `MOD-14`, `MOD-15`, `MOD-17`, `MOD-18`.
- **Allowed Dependencies**: Read/governance/HITL APIs of `MOD-03`, `MOD-06`, `MOD-07`, `MOD-09`, `MOD-10`, `MOD-11`, `MOD-13` (authenticated takeover stream), `MOD-14` (status/takeover), `MOD-15`, `MOD-17`, `MOD-18`.
- **Forbidden Dependencies**: Must never bypass `MOD-03`/`MOD-17` to mutate tasks/automations/interactions directly, expose entered OTPs/passwords to `MOD-04` LLM prompts or logs, or call external SaaS execution harnesses directly.
- **Independent Testability (`AP-08`)**: Frontend tested against OpenAPI contracts; FastAPI BFF routes and handoff ticket verification tested via `TestClient` integration tests.

### `MOD-03`: Deterministic Task Manager *(Owns Internal `HumanInteractionManager`)*
- **Purpose**: Authoritative orchestrator of macro-task lifecycle (`CREATED -> QUEUED -> RUNNING -> SUSPENDING_FOR_USER -> WAITING_FOR_USER -> COMPLETED | FAILED | CANCELLED | CANCELLED_AFTER_EXTERNAL_COMMIT | EXPIRED`), durable `orbi_app.task_lifecycle_outbox` + Redis queuing, configurable execution budgets (steps, wall-clock TTL, LLM spend/token caps), retries, and **centralized Human-in-the-Loop (HITL) interaction orchestration via internal `HumanInteractionManager`** (no separate top-level module): managing persistent `InteractionRequest` lifecycles across all 5 interaction types (`INFORMATION_REQUEST`, `APPROVAL_REQUEST` with `ADR-004` cryptographic action-binding, `SECURE_INPUT_REQUEST`, `HUMAN_TAKEOVER`, `PHYSICAL_ACTION_REQUEST`) via pre-mutation OpenFGA check (`403 AUTHZ_DENIED` leaves pending state untouched), 3-step `interaction_version` CAS (`RESPONSE_RECEIVED -> VALIDATING -> RESOLVED|VALIDATION_FAILED_RETRYABLE|REJECTED|INVALIDATED|CANCELLED`), two-phase checkpoint-first suspension (`SUSPENDING_FOR_USER` -> save & verify `pending_checkpoint_id` -> `WAITING_FOR_USER`), bounded-lease + `claim_epoch`-fenced `RESUME_TASK` execution claims (retaining `resume_token_id` until turn outcome commits and recovering expired `RUNNING` leases with `task_lifecycle_processed_events` + write-ahead `step_execution_receipts` reconciliation / `UNCERTAIN_EXECUTION_RECONCILIATION` escalation for non-idempotent `UNKNOWN_OUTCOME` calls), outbox-backed `MEMORY_CLARIFICATION_DECIDED` delivery to `MOD-10`, duplicate/stale/cross-channel response rejection, crash reconciler recovery, and cascade cancellation on task/automation cancel. Serves as the single task execution engine for both user-initiated requests and automation-triggered runs from `MOD-17`.
- **Status**: `[CONFIRMED]` (Zone 1: `orbi-core`).
- **Owned State**: Authoritative `tasks` (with monotonic `task_version`, `pending_checkpoint_id`, `verified_checkpoint_id`, `resume_token_id`, `claim_epoch`, `lease_expires_at`, `claimed_by_worker_id`), `task_steps`, `task_budgets`, `step_execution_receipts` (`action_idempotency_key`, `PREPARED | DISPATCHING | CONFIRMED_SUCCESS | CONFIRMED_FAILURE_* | UNKNOWN_OUTCOME`), **`interaction_requests`** (with monotonic `interaction_version`, `response_idempotency_key`), **`approval_requests`** (with `binding_digest`, `policy_version`, `expires_at`), **`task_lifecycle_outbox`** (`DELIVER_INTERACTION_PROMPT`, `RESUME_TASK`, `MEMORY_CLARIFICATION_DECIDED`, `claim_epoch`, `lease_expires_at`), `task_lifecycle_processed_events`, and encrypted short-TTL `ephemeral_secret_handles` (never passed to `MOD-04`/logs/checkpoints) in PostgreSQL (`orbi_app`); Redis transport queues and distributed locks.
- **Public Interfaces**:
  - *Inbound*: `create_task()`, `dispatch_automation_task()` (from `MOD-17` with `automation_id`, `execution_id`, `automation_generation`, `responsibility_id`, scoped grant), `cancel_task()`, **`create_interaction()`** (from `MOD-04`, `MOD-08`, `MOD-10`, `MOD-13`/`MOD-14`), **`submit_interaction_response()`** (from `MOD-01` / `MOD-02` with auth + pre-mutation OpenFGA verify + 3-step CAS), **`suspend_for_interaction()`** (two-phase checkpoint-first protocol), and `report_turn_outcome()` (from `MOD-04`).
  - *Outbound*: Dispatches bounded cognitive turns / checkpoint resumptions (`RESUME_TASK` via `task_lifecycle_outbox` bounded-lease `claim_epoch` CAS, clearing `resume_token_id` atomically on turn completion) to `MOD-04`, reliably delivers `MEMORY_CLARIFICATION_DECIDED` via `task_lifecycle_outbox` (plus periodic reconciler) to `MOD-10.submit_clarification_decision()`, binds ephemeral secret handles to `MOD-08`, pushes multi-channel notification/handoff requests via outbox (`DELIVER_INTERACTION_PROMPT`) to `MOD-18`, pre-triage queries to `MOD-05`, completed/failed task outcomes to `MOD-18` (which notifies `MOD-01`/`MOD-02` and triggers `MOD-17` callbacks), and redacted lifecycle events to `MOD-15`.
- **Allowed Dependencies**: PostgreSQL (`orbi_app`), Redis (transport only), `MOD-04`, `MOD-05`, `MOD-08`, `MOD-09` (responder/approver/session_controller & automation execution verification), `MOD-10` (outbox/reconciler clarification callback), `MOD-15`, `MOD-17`, `MOD-18`.
- **Forbidden Dependencies**: Must never embed LLM reasoning prompts, assume PG and `langgraph_checkpoints` commit in a single cross-store atomic transaction, treat `claim_epoch` or `approval_requests` consumption as reversing or proving completion of an already-transmitted external request (`DISPATCHING` -> `UNKNOWN_OUTCOME`), allow expired-lease zombie workers (`STALE_CLAIM_EPOCH_FENCED`) to overwrite resumed task state, delegate task/approval truth to LangGraph checkpoint internals, mutate pending interactions on unauthorized `403 AUTHZ_DENIED` requests, expose `SECURE_INPUT_REQUEST` secrets to `MOD-04`/`MOD-10`/`MOD-15`, treat `INFORMATION_REQUEST` answers as `APPROVAL_REQUEST` grants, own long-term cron/event/condition trigger catalogs (`MOD-17`), or embed execution harness SDKs (`MOD-12`–`MOD-14`).
- **Independent Testability (`AP-08`)**: Deterministic FSM transition, budget exhaustion, expiration TTL, unauthorized non-invalidation (`AUTHZ_DENIED`), explicit `REJECTED` vs. drift `INVALIDATED`, 3-step `interaction_version` CAS concurrency, two-phase checkpoint suspension crash recovery, outbox `RESUME_TASK` stale-`RUNNING` lease recovery, `UNKNOWN_OUTCOME` escalation & `MEMORY_CLARIFICATION_DECIDED` delivery (`EVAL-04`), multi-channel handoff, and all 26 HITL evaluation scenarios (`HITL-EVAL-01`–`26`) with mocked `MOD-04`/`MOD-08`/`MOD-10`/`MOD-17`/`MOD-18`.

### `MOD-04`: Agent Orchestrator & Runtime (LangGraph + Model Adapters)
- **Purpose**: Executes System-2 cognitive workflows via a **Manager/Planner Agent** and domain **Specialized Agents** inside LangGraph (`ADR-001`). Enforces **Provider-Independent Model Adapters** (`ADR-003`), executes the mandatory **Agent & Tool Discovery Sequence** (`Clarification A`, `ADR-002`), and empowers authorized agents to autonomously reason over ongoing responsibilities and arrange or adapt future/recurring/event/condition work via `automation.*` `ToolCallIntent` calls (`ADR-009`).
- **Status**: `[CONFIRMED]` (Zone 1: `orbi-core`).
- **Owned State**: Ephemeral turn-scoped reasoning scratchpad only; zero ownership of macro-task lifecycle (`AP-03`) or persistent automation schedules (`ADR-009`). Must never hold live LLM sessions sleeping to wait for future times or events.
- **Public Interfaces**:
  - *Inbound*: `execute_cognitive_turn(task_context, turn_budget, user_principal, household_context, scoped_responsibility_ctx)` from `MOD-03`.
  - *Outbound*: Queries `MOD-05` (Decision Service), `MOD-06` (Agent Registry), `MOD-07` (Tool Registry), `MOD-09` (OpenFGA Stage-1 discovery filter), `MOD-10` (Memory Manager), `MOD-11` (published skill instruction loader), and submits all `ToolCallIntent` requests (including `automation.*` calls) strictly to `MOD-08`.
- **Allowed Dependencies**: `MOD-05`, `MOD-06`, `MOD-07`, `MOD-08`, `MOD-09` (read-only discovery filter), `MOD-10`, `MOD-11` (published skill instruction loader), `MOD-15`, configured `ModelAdapter` providers.
- **Forbidden Dependencies**: **Strictly prohibited** from inventing tool identifiers, granting self-permissions, mutating `MOD-17` automations directly bypassing `MOD-08`, inheriting creator permissions on delegated automations, importing `MOD-12` SaaS SDKs, importing `MOD-13` Playwright, connecting to `MOD-14`, executing skill scripts directly, or reading credential vaults (`AP-01`, `AP-03`).
- **Independent Testability (`AP-08`)**: Tested deterministically using stubbed `ModelAdapter` responses, mocked OpenFGA discovery filters, and fake `MOD-08` Gateway results.

### `MOD-05`: Provider-Independent Decision Service
- **Purpose**: Structured System-1 decision abstraction (`noul`, `choice`, `score`) supporting intent triage, agent routing, risk pre-scoring, and loop termination (`Clarification B`, `ADR-003`). Operates cleanly **without** Jev via deterministic rule evaluators and LLM-based fallback providers; **Jev by TypeSafe** is integrated strictly as an **optional provider** pending `EVAL-01`.
- **Status**: `[CONFIRMED]` Architecture / `[EVALUATION REQUIRED]` Jev Provider (`EVAL-01`).
- **Owned State**: Provider priority chains, per-provider timeout budgets, and per-provider confidence threshold profiles (`CON-12`).
- **Public Interfaces**:
  - *Inbound*: `decide_noul(ctx, timeout_ms)`, `decide_choice(ctx, options, timeout_ms)`, `decide_score(ctx, rubric, timeout_ms)` called by `MOD-03`, `MOD-04`, or `MOD-08` (advisory risk escalation only).
  - *Outbound*: Returns typed `DecisionResult(value, confidence, provider_used, fallback_triggered, latency_ms)` and logs every call/fallback to `MOD-15`.
- **Fallback & Timeout Contract (`Clarification B`)**:
  1. Attempt configured primary provider (e.g., `DeterministicRuleProvider` for exact heuristics, or optional `JevDecisionProvider` if enabled) under a strict hard timeout (`timeout_ms`).
  2. On timeout, HTTP error, circuit-breaker open, or sub-threshold confidence, automatically fall back to configured secondary provider (`DeterministicRuleProvider` or `LLMDecisionProvider` via `MOD-04` `ModelAdapter`).
  3. On total decision failure, return deterministic safe default (e.g., route to Manager LLM or escalate risk tier—never lower risk or skip authorization).
- **Forbidden Dependencies**: Cannot authorize access (`AP-02` belongs exclusively to `MOD-09`), mutate tasks, or invoke tools.
- **Independent Testability (`AP-08`)**: Contract test suite across `DeterministicRuleProvider`, `LLMDecisionProvider`, and optional `JevDecisionProvider` simulating timeouts, network faults, and low-confidence fallbacks.

### `MOD-06`: Central Agent Registry
- **Purpose**: Declarative catalog of all agent personas (`ManagerAgent`, `EmailAgent`, `MediaAgent`, `BrowserAgent`, `DesktopAgent`, `SkillAuthorAgent`), defining role metadata, `ModelAdapter` profile/budget policy, configured tool/skill allowlists, and OpenFGA principal IDs (`agent:<id>`).
- **Status**: `[CONFIRMED]` (Zone 1: `orbi-core` / `orbi_app`).
- **Public Interfaces**: `select_agent_candidates()`, `get_agent_definition(agent_id)`, `register_agent()`.
- **Allowed Dependencies**: PostgreSQL (`orbi_app`), `MOD-15`.
- **Forbidden Dependencies**: Never executes LangGraph loops or overrides OpenFGA policies.
- **Independent Testability (`AP-08`)**: CRUD and schema validation tests against isolated test database.

### `MOD-07`: Central Tool Registry
- **Purpose**: Authoritative metadata catalog of every callable tool (including the `automation.*` management tool family), native/UIA/vision Windows capability, and published Markdown skill entry: versioned JSON Input/Output schemas, target isolation zone (`ZONE_1_API`, `ZONE_1_AUTOMATION`, `ZONE_2_BROWSER`, `ZONE_2_SANDBOX`, `ZONE_3_WINDOWS`, `FUTURE_IOT`), semantic vs. volatile argument metadata (`CON-10`), idempotency & reconciliation policy (`idempotent`, `external_idempotency_mode: PROVIDER_IDEMPOTENCY_KEY | RECONCILABLE_READ_PROBE | NON_IDEMPOTENT_NO_RECONCILE`, `idempotency_window_seconds`, `reconciliation_probe_tool_id`), and static **Sensitivity Tier** (`READ_ONLY`, `LOW_RISK_WRITE`, `SENSITIVE_WRITE`, `IRREVERSIBLE`).
- **Status**: `[CONFIRMED]` (Zone 1: `orbi-core` / `orbi_app`).
- **Public Interfaces**: `get_tool_definition(tool_id, version)`, `get_tools_for_agent_config(agent_id)`, `register_tool()`.
- **Allowed Dependencies**: PostgreSQL (`orbi_app`), `MOD-15`.
- **Forbidden Dependencies**: Holds zero runtime credentials and executes zero tool logic.
- **Independent Testability (`AP-08`)**: Schema compatibility, semantic-field tagging, idempotency/reconciliation policy, and risk-tier integrity unit tests.

### `MOD-08`: Tool Execution Gateway
- **Purpose**: **The non-bypassable execution chokepoint (`AP-01`)**. Receives `ToolCallIntent` from `MOD-04` (or `MOD-11-SANDBOX` script sub-intents) and `READ_ONLY` `ProbeIntent` calls from `MOD-17`'s non-LLM `ConditionEvaluator`, validates tool existence and schemas against `MOD-07`, binds a deterministic **`action_idempotency_key`** (`sha256(tenant_id, task_id, execution_id, logical_step_id, tool_id, tool_version, canonical_arguments_hash, target_resource, approval_id?)`)—where `execution_id` and `logical_step_id` identify the stable logical execution/step rather than a worker attempt so **`execution_id` and `action_idempotency_key` remain strictly unchanged across worker crashes, lease recovery, `W1 -> W2` worker replacement, LangGraph checkpoint restoration, and task resumption/retries (excluding worker IDs, `claim_epoch`, `attempt_count`, `resume_token_id`, and recovery generations)**—into write-ahead `orbi_app.step_execution_receipts` (`PREPARED -> DISPATCHING -> CONFIRMED_SUCCESS | CONFIRMED_FAILURE_* | UNKNOWN_OUTCOME`), enforces byte-for-byte immutable retry identity (retries never alter approved args/target/identity), executes Stage-2 OpenFGA authorization (`MOD-09`), verifies **cryptographically action-bound approvals (`ADR-004`, `Clarification C`)**, enforces the **Pre-Dispatch Cancellation, `task_version`, `claim_epoch` & `automation.generation` Gate** immediately before every external dispatch (`STALE_CLAIM_EPOCH_FENCED` on expired-lease zombie workers; commits write-ahead `DISPATCHING` before transmission while explicitly bounding `claim_epoch`/approval consumption to Orbi-side state; replays `CONFIRMED_SUCCESS`, retries `PROVIDER_IDEMPOTENCY_KEY` with the same key, probes `RECONCILABLE_READ_PROBE`, or prohibits blind automatic retry and escalates `NON_IDEMPOTENT_NO_RECONCILE` `UNKNOWN_OUTCOME` via `MOD-03` `UNCERTAIN_EXECUTION_RECONCILIATION`; never claims rollback of committed external actions -> `CANCELLED_AFTER_EXTERNAL_COMMIT`), injects persistent vault credentials or single-use `SECURE_INPUT_REQUEST` `ephemeral_secret_handle` secrets (zero exposure to `MOD-04`/checkpoints/logs, masking browser DOM fields), enforces session lockout during `HUMAN_TAKEOVER` + post-takeover verification probes, dispatches to execution zones (`MOD-12`, `MOD-13`, `MOD-11-SANDBOX`, `MOD-14`, `MOD-17`), sanitizes results, and logs to `MOD-15`.
- **Status**: `[CONFIRMED]` (Zone 1: `orbi-core`).
- **Owned State**: Write-ahead idempotency & execution receipts (`step_execution_receipts` with `action_idempotency_key` in `orbi_app`) and active mTLS relay session routing for `MOD-14`.
- **Public Interfaces**:
  - *Inbound*: `execute_tool_intent(ToolCallIntent)`, `execute_readonly_probe(ProbeIntent)` (from `MOD-17` `ConditionEvaluator` and post-`HUMAN_TAKEOVER`/`PHYSICAL_ACTION_REQUEST`/`UNKNOWN_OUTCOME` verification), `resume_approved_intent(approval_id, action_digest)` (from `MOD-03`).
  - *Outbound*: `MOD-09.check()`, `MOD-03.create_interaction()` (`APPROVAL_REQUEST`, `SECURE_INPUT_REQUEST`, `HUMAN_TAKEOVER`, `UNCERTAIN_EXECUTION_RECONCILIATION`), harness dispatch (`MOD-12`, `MOD-13`, `MOD-11-SANDBOX`, `MOD-14`), `MOD-17` (`automation.*` adapter), `MOD-15.record_audit()`.
- **Allowed Dependencies**: `MOD-03`, `MOD-05` (advisory risk escalation only), `MOD-07`, `MOD-09`, `MOD-11-SANDBOX`, `MOD-12`, `MOD-13`, `MOD-14`, `MOD-15`, `MOD-17`, Secret Vault, Ephemeral Secret Buffer.
- **Forbidden Dependencies**: Never asks an LLM whether to waive OpenFGA or bypass an expired/mismatched approval, never dispatches to a task/automation invalidated in PG (`cancellation_requested` / stale `generation` / stale `claim_epoch`), never alters approved arguments/target/action identity across retries, never blindly auto-retries `NON_IDEMPOTENT_NO_RECONCILE` tools left in `DISPATCHING` / `UNKNOWN_OUTCOME`, never assumes `claim_epoch` can recall an already-dispatched external request, never re-executes external side effects when `CONFIRMED_SUCCESS` exists, never returns `SECURE_INPUT_REQUEST` secrets back into `MOD-04` observations or `MOD-15` plaintext logs, and never permits condition probes to execute side-effecting write tools.
- **Independent Testability (`AP-08`)**: Contract tests proving fail-closed denial on OpenFGA errors, rejection on invented tool IDs, automatic invalidation when arguments/target/policy_version differ from approved digest, pre-dispatch cancellation/`claim_epoch` zombie fencing, immutable `action_idempotency_key` retry identity, write-ahead `DISPATCHING -> UNKNOWN_OUTCOME` provider dedup, `READ_ONLY` reconciliation, no-blind-retry escalation (`HITL-EVAL-25`, `HITL-EVAL-26`), and zero secret leakage in sanitized outputs.

### `MOD-09`: Authorization & Policy Engine (OpenFGA)
- **Purpose**: Externalized Relationship-Based Access Control (ReBAC) engine (`AP-02`) running as an isolated container (`orbi-openfga`), modeling **tenant-extensible ownership (`ADR-002`: `personal`, `household`, and extensible `organization` boundary)** across `tenant`, `user`, `agent`, `tool`, `skill`, `instance`, `resource`, `memory_unit`, **`interaction_request`**, **`approval_request`**, **`responsibility`**, **`automation`**, and **`permission_envelope`** entities (`ADR-009`). ### `MOD-10`: Memory Manager
- **Purpose**: Canonical memory domain owner (`ADR-007`, `ADR-008`, [memory-architecture.md](file:///f:/Projects/Orbi/docs/02-hld/memory-architecture.md))—explicitly **not** Cognee itself or a thin wrapper over Cognee's default retrieval API. Owns end-to-end **memory lifecycle** (ingestion, belief-preserving correction, `NEEDS_CLARIFICATION` quarantine integrated with `MOD-03`'s `HumanInteractionManager`, and 9-step cascading deletion with pre-scrub `deletion_dependency_manifest` via transactional `memory_sync_outbox`), the **5-stage Hybrid Retrieval Pipeline** (with mandatory 4-branch pre-fusion authoritative PG deletion/tombstone gate), canonical `MemoryUnit` identity (terminal tombstone `deletion_state = 'COMPLETED'`), **provenance & trust quarantine** (`TrustTier`), **true bitemporal validity** (**valid time** `valid_from`/`valid_to` + **system time** `recorded_from`/`recorded_to` + `superseded_by`), and **mandatory per-branch & per-source pre-fusion OpenFGA authorization enforcement**. **Cognee** is encapsulated strictly as an internal, replaceable adapter (**`CogneeAdapter`**) rather than defining `MOD-10` itself (`EVAL-03`, `EVAL-07`).
- **Status**: `[CONFIRMED]` Memory Lifecycle, Pipeline Orchestration, Provenance, Bitemporal Semantics & Per-Branch Authz / `[PROPOSED - EVALUATION REQUIRED]` PG FTS vs. Genuine BM25, RRF, Reranking & `CogneeAdapter`/PG Backends (`EVAL-03`, `EVAL-07`).
- **Owned Internal Sub-Components (`orbi-core` Zone 1)**:
  1. **`QueryUnderstandingEngine` (`QueryUnderstandingPort`)**: Provider-independent 3-tier analyzer (Tier 1 deterministic lexical/date parser `< 5 ms`, Tier 2 optional `MOD-05` `choice`/`noul`, Tier 3 conditional LLM fallback) extracting `intent`, `entities`, `keywords`, bitemporal `temporal_constraint` (`CURRENT | HISTORICAL | RANGE` + optional `as_of_recorded_ts`), `use_graph_traversal`, and `activated_branches` without mandatory LLM calls.
  2. **`BranchOrchestrator` & 4 Retrieval Adapters (`RetrievalBranchPort`)**: Runs activated branches concurrently with per-branch `timeout_ms`: `VectorBranch` (via replaceable `CogneeAdapter`), `BM25Branch` (`[PROPOSED]`, configurable `LexicalBackendPort` separately evaluating **PostgreSQL FTS** [`tsvector`, `tsquery`, `ts_rank`/`ts_rank_cd` — never labeled BM25] vs. **Genuine BM25** [`pg_search`] in `EVAL-07`), `GraphBranch` (bounded 1–2 hop traversal via replaceable `CogneeAdapter` preserving `source_memory_unit_ids[]`), and selective `TemporalBranch` (PostgreSQL `orbi_memory` interval SQL handling `CURRENT`, `HISTORICAL` without `superseded_by IS NULL`, and `RANGE` overlap).
  3. **`BranchAuthzFilter` (Authz + Authoritative Pre-Fusion Tombstone Gate)**: Enforces **both** the authoritative PG `orbi_memory` deletion/tombstone check (`deletion_state == 'ACTIVE'` and no matching `memory_deletion_requests` tombstone—blocking stale `CogneeAdapter` hits during `PENDING_PROPAGATION` or `FAILED_REQUIRES_RECONCILIATION`) **and** two-layer OpenFGA (`MOD-09`) checks inside **every** branch (`private_user`, `shared_tenant`, `custom_acl`) *before* candidates exit to Fusion, applying the **7-rule Source-Level Graph Authorization Invariant** (`CON-13`, `FR-MS-12`).
  4. **`CandidateFusionEngine` (`CandidateFusionPort`)**: Normalizes/fuses incompatible branch scales (initial proposal: weighted Reciprocal Rank Fusion / `RRF`, $k = 60$, `[PROPOSED - EVAL-07]`) using **`memory_unit_id` as the SOLE authoritative deduplication/merge key** (`content_hash` is never used to merge records), preserving multi-branch provenance/ranks/scores and capping at `candidate_limit`.
  5. **`RerankingEngine` (`RerankerPort`)**: Replaceable reranker (`NoOpReranker`, `LocalCrossEncoderReranker`, `APIReranker`, `ConditionalLLMReranker` disabled by default) re-scoring fused candidates to `final_context_limit` with selective bypass rules and automatic RRF fallback on timeout (`FR-MS-11`).
  6. **`PostgresMemoryCatalog`, `MemoryResolutionEngine`, `ExplicitDeletionOrchestrator`, `MemorySyncOutboxDispatcher` & Internal Replaceable `CogneeAdapter`**: `orbi_memory` owns canonical `MemoryUnit` IDs (`deletion_state: ACTIVE | REQUESTED | PENDING_PROPAGATION | COMPLETED | FAILED_REQUIRES_RECONCILIATION`), `tenant_id`/`owner_principal` ACL scopes, `TrustTier`, bitemporal intervals (`CON-16`), and lexical indexes. **`MemoryResolutionEngine`** resolves incoming candidates to `CREATE`, `REINFORCE`, `REFINE`, `SUPERSEDE` *(separating real-world succession from belief correction)*, or `NEEDS_CLARIFICATION` (`memory_resolution_candidates`, never retrieved prematurely; solicits clarification via `MOD-03`'s `HumanInteractionManager` -> `MOD-18`, receives `MEMORY_CLARIFICATION_DECIDED` reliably via `orbi_app.task_lifecycle_outbox` + periodic `RESOLVED` vs. `PENDING_CLARIFICATION` reconciler, deduplicates via `memory_sync_processed_events` in `submit_clarification_decision()`, and preserves `original_source_provenance` & `original_trust_tier`). **`ExplicitDeletionOrchestrator`** executes the 9-step deletion workflow cleanly separated from supersession: captures non-plaintext `deletion_dependency_manifest` *before* scrubbing plaintext/provenance, enforces `deletion_state != 'ACTIVE'` across all 4 branches, removes deleted `source_memory_unit_ids[]` and recomputes/prunes graph nodes, sets terminal `deletion_state = 'COMPLETED'` tombstones, and keeps redacted `MOD-15` proof. Atomic **`memory_sync_outbox`** events publish via leased worker -> Redis -> idempotent sync consumers with bounded retries and `DEAD_LETTERED` handling (`CON-14`).
- **Owned State**: Canonical `MemoryUnit` catalog (`confirmation_count`, `corroborating_provenance[]`, `deletion_state`), `memory_resolution_candidates`, `memory_deletion_requests` (with pre-scrub `deletion_dependency_manifest`), bitemporal records, lexical indexes, `memory_sync_outbox`, and `memory_sync_processed_events` in PostgreSQL `orbi_memory`, plus internal replaceable `CogneeAdapter` vector/graph stores (`EVAL-03`).
- **Public Interfaces**: `retrieve_hybrid_memory(MemoryQueryRequest)`, `resolve_and_commit_memory(candidate_proposal)`, `submit_clarification_decision(candidate_id, interaction_id, verified_actor, decision_payload, idempotency_key)`, `request_explicit_deletion(selector, requester)` (`FR-MS-14`), and `run_retrieval_eval_suite()` (`EVAL-07`).
- **Allowed Dependencies**: `MOD-03` (`HumanInteractionManager` clarification & delete-disambiguation requests), `MOD-05` (Tier-2 query classification), `MOD-09` (mandatory per-branch/per-source OpenFGA checks & ACL tuple cleanup), `MOD-15` (retrieval, fallback & mutation audit), PostgreSQL `orbi_memory`, Redis (transport only), `BlobStoragePort`, and internal replaceable `CogneeAdapter`.
- **Forbidden Dependencies**: Never exposes `CogneeAdapter` directly to `MOD-04`, `MOD-02`, or external callers; never lets unverified `memory_resolution_candidates` enter active retrieval; never merges fusion candidates by `content_hash`; never applies universal `superseded_by IS NULL` to historical/range queries; never unions graph source permissions; never leaks stale deleted or unauthorized entities/edges/summaries into Fusion, Reranking, or `MOD-04`; never allows `untrusted_external` facts to silently close `recorded_to` or set `superseded_by` on `user_explicit` facts (`CON-16`); never stores task state, OpenFGA tuples, OAuth secrets, `SECURE_INPUT_REQUEST` OTPs/passwords, or executable skill code (`AP-04`).
- **Independent Testability (`AP-08`)**: Stage-by-stage contract tests (Bitemporal Historical + Combined Valid/System-Time Tests -> 5-Outcome Memory Resolution, Outbox/Idempotent HITL `NEEDS_CLARIFICATION` Callback & Reconciler [`HITL-EVAL-23`] -> 9-Step Explicit Deletion, Pre-Scrub Manifest, Terminal `COMPLETED` Tombstone & 4-Branch Pre-Fusion Gate vs. Supersession -> PG FTS vs. Genuine BM25 Benchmark -> OpenFGA Multi-Hop & Convergent Entity `"Project Apollo"` Leakage Tests -> `memory_unit_id`-Only Deduplication -> Transactional Outbox Recovery -> Graceful `CogneeAdapter` Outage Fallback) plus `EVAL-07` (`MEM-EVAL-01`–`14`, `MEM-RES-01`–`10`, `MEM-DEL-01`–`06`).
